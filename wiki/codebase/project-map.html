Project Map

The repository studies stellar ages and cosmic chronometers. It is a research workspace organized around notebooks, not an application with one command-line entry point (README.md:1-16).

Repository boundaries

  • src/: reusable project-owned numerical helpers.
  • scripts/: downloads and reproducible data transformations.
  • notebooks/: analyses, experiments, and presentation.
  • data/raw/: immutable downloaded inputs.
  • data/processed/: reproducible derived tables.
  • papers/: immutable literature sources.
  • ceridwen/: SED-fitting Git submodule, not project-owned source.
  • external/CCcovariance/: covariance reference submodule.
  • external/fsps/: stellar-population synthesis submodule and data tree.
  • wiki/: generated code-reading documentation.

The three submodule paths and remotes are declared in .gitmodules:1-9.

Entry points

There is no single scientific main() function. main.py:1-6 is the project scaffold and only prints a greeting. Scientific execution begins in a notebook or one of these functions:

  • scripts/build_borghi2022_legac_dr2_subset.py:176, table build.
  • scripts/download_legac_dr2_spectra.py:113, spectrum download.
  • scripts/download_cosmos2015_legac_dr2_photometry.py:116, photometry match.
  • ceridwen/ceridwen/fit.py:67, high-level Ceridwen fit.
  • ceridwen/ceridwen/sampler/runner.py:275, sampler dispatch.

Environments

The root project requires Python 3.14 and contains Astropy, emcee, milespy, Prospector, and FSPS dependencies (pyproject.toml:1-33). Ceridwen is an independent package requiring Python 3.11 or newer and JAX/BlackJAX (ceridwen/pyproject.toml:5-82). Separate environments prevent dependency constraints from being forced together.

Ownership

Code ownership:

  • A notebook cell is project orchestration and may be exploratory.
  • src/ is reusable project behavior.
  • ceridwen/ceridwen/ is third-party package implementation.
  • external/ is reference or upstream implementation.

The inspected Ceridwen checkout is submodule commit e0252a3. Its working tree contains local changes, so this wiki documents the live checkout rather than only the upstream commit.
