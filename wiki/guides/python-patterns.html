Python Patterns

Function

A function names a transformation from inputs to outputs. Read its signature, then find its return statements before studying intermediate lines.

  • src/mocks.py:26-33, true_ages(...) returns stellar ages.
  • src/mocks.py:41-108, make_mock(...) returns a MockSample.
  • ceridwen/ceridwen/model/model.py:298-351, predict(theta) returns a dict.

Question: which of those functions has a filesystem side effect? None.

Dataclass

A dataclass declares a data record. It stores results without necessarily owning the algorithm that produced them.

  • src/mocks.py:15-23: MockSample stores one simulated catalogue.
  • ceridwen/ceridwen/sampler/runner.py:69-128: SamplingResult stores output.

Read field names as the object’s data contract. Then search where the class is constructed to find the producing algorithm.

src/mocks.py:15-23

@dataclass
class MockSample:
    """One realisation. `age_obs` is what an observer would report."""

    z: np.ndarray
    age_true: np.ndarray      # Gyr, cosmology + intrinsic scatter, no measurement error
    age_obs: np.ndarray       # Gyr, after systematics and noise
    age_err: np.ndarray       # Gyr, the reported 1-sigma uncertainty
    truth: dict               # the input parameters, for recovery tests

There are no methods here. The class names five fields and their meaning; the producing function is elsewhere.

Closure

A closure is an inner function that remembers variables from its enclosing function. log_prob_factory returns log_prob, which remembers interp, obs, err, sigma, lo, and hi without receiving them again (src/lick_inference.py:11-24).

src/lick_inference.py:11-24

def log_prob_factory(interp, obs, err, sigma, lo, hi):
    """Return the vectorized Borghi et al. (2022a) Equation 7 likelihood."""

    def log_prob(theta):
        theta = np.atleast_2d(theta)
        inside = np.all((theta >= lo) & (theta <= hi), axis=1)
        out = np.full(len(theta), -np.inf)
        if inside.any():
            points = np.column_stack([theta[inside], np.full(inside.sum(), sigma)])
            chi2 = np.sum(((obs - interp(points)) / err) ** 2, axis=1)
            out[inside] = -0.5 * chi2
        return out

    return log_prob

The outer function receives fixed galaxy data once. The inner function receives only each proposed theta; Python retains the six outer names in the closure.

Class and inheritance

Inheritance expresses “is a specialized kind of.” Photometry, Spectrum, and Lines inherit storage and masking from Observation, then replace projection behavior:

  • Base contract: ceridwen/ceridwen/observation/base.py:25-89.
  • Abstract-style predict: base.py:273-301.
  • Photometry implementation: photometry.py:245-267.
  • Spectrum implementation: spectrum.py:493-557.

When reading inheritance, compare the same method name across parent and child.

Composition

Composition means one object contains collaborating objects. SedModel owns a CSP, observations, priors, and transforms rather than inheriting their code (ceridwen/ceridwen/model/model.py:141-167). This is Ceridwen’s central design.

Adapter

An adapter gives different external libraries one common interface. SamplerAdapter.run(...) defines the protocol, while NUTS and nested-sampling classes implement it (ceridwen/ceridwen/sampler/runner.py:215-268).

The caller run_sampler depends on the protocol, not BlackJAX’s internal API (runner.py:275-366).

Decorator

A decorator changes how a function runs while preserving its callable form.

  • @jax.jit compiles a numerical function: runner.py:349-363.
  • @classmethod passes the class as cls: ssp_data.py:402-450.
  • @property exposes a method like an attribute: base.py:216-234.

Read the decorator before the function because it changes execution.

src/cosmology.py:10-12

@u.quantity_input #@ calls a decorator, quantity_input is the astropy function
def H(z, H0: u.Quantity[u.km/u.s/u.Mpc], omega_m):
    return E(z, omega_m) * H0

@u.quantity_input validates the annotated units before the three-line function body runs.

Module exports

An __init__.py defines convenient public names. For example, ceridwen/ceridwen/ssps/__init__.py:7-18 exports grid containers and fetching helpers. Start there, then open the defining module.

JAX static versus traced values

This distinction explains much of Ceridwen’s structure:

  • Static Python values define shapes, object types, and observation lists.
  • Traced JAX arrays contain parameter values changing during sampling.
  • Static branches are resolved once during compilation.
  • Python cannot branch on the numerical value of a traced array.

Examples:

  • Observation setup precomputes matrices before JIT: ceridwen/ceridwen/model/model.py:197-211.
  • The observation loop becomes compiled operations: ceridwen/ceridwen/csp/csp_afe.py:1096-1116.
  • theta arrays remain differentiable inside prediction: ceridwen/ceridwen/model/model.py:298-351.

ceridwen/ceridwen/sampler/runner.py:348-358

# ── Log-likelihood: sum over observations, no prior ───────────────────
@jax.jit
def loglike_fn(theta: dict[str, Array]) -> Array:
    predictions = model.predict(theta)
    lnl = jnp.zeros(())
    for key, lhood in zip(_keys, _likelihoods):
        y_k, sig_k, mask_k = _static_data[key]
        mu_k    = predictions[key]
        lnl_k, _ = lhood(y_k, mu_k, sig_k, mask_k, params=theta)
        lnl = lnl + lnl_k
    return lnl

theta is traced numerical data. The tuples _keys and _likelihoods were built outside this function, so JAX sees a fixed loop structure.
