Choose an instance

  • Use a Linux image with Jupyter, SSH, and CUDA 12.
  • Require at least 12 GB GPU memory and 30 GB disk.
  • Prefer a 24 GB RTX 3090 or 4090 for headroom.

The bootstrap exits if Linux, NVIDIA visibility, or the 12 GB memory floor is missing. It never silently falls back to CPU.

scripts/bootstrap_vast_ai.sh:14-32

if ! command -v nvidia-smi >/dev/null 2>&1; then
    echo "nvidia-smi is unavailable; launch a Vast.ai NVIDIA GPU instance." >&2
    exit 1
fi

if (( GPU_MEMORY_MIB < MINIMUM_GPU_MEMORY_MIB )); then
    echo "GPU has ${GPU_MEMORY_MIB} MiB; notebook 07 requires at least 12000 MiB." >&2
    exit 1
fi

Clone the project

Open the instance terminal and clone into its persistent workspace. Submodules are required because Ceridwen lives inside this repository.

cd /workspace
git clone --recurse-submodules \
  https://github.com/potatoist314/cosmic-chronometers-jwst.git
cd cosmic-chronometers-jwst

Transfer private data

Run these commands locally, replacing <INSTANCE_ID>. Git does not contain the LEGA-C spectra, matched photometry, or high-resolution SSP grid.

vastai copy "local:$PWD/data/raw" \
  "C.<INSTANCE_ID>:/workspace/cosmic-chronometers-jwst/data/"

vastai copy "local:$PWD/ceridwen/amist_c3k_hr_krou_afe.h5" \
  "C.<INSTANCE_ID>:/workspace/cosmic-chronometers-jwst/ceridwen/"

The required remote paths are:

  • data/raw/legac_dr2/legaCdr2.fits.gz
  • data/raw/legac_dr2/sp/
  • data/raw/cosmos2015/cosmos2015_legac_dr2_photometry_1arcsec.fits
  • ceridwen/amist_c3k_hr_krou_afe.h5

Bootstrap and verify

Run the maintained setup script from the remote project root:

bash scripts/bootstrap_vast_ai.sh

It creates an isolated Python 3.11 environment, installs CUDA JAX and Ceridwen, verifies GPU float64 execution, runs Ceridwen's check, and registers the notebook kernel.

scripts/bootstrap_vast_ai.sh:70-90

JAX_PLATFORMS=cuda JAX_ENABLE_X64=1 "${PYTHON_BIN}" - <<'PY'
import jax
import jax.numpy as jnp

devices = jax.devices()
if not devices or any(device.platform != "gpu" for device in devices):
    raise SystemExit(f"Expected CUDA GPU devices, found {devices}")
value = jnp.ones(1, dtype=jnp.float64).block_until_ready()
PY

"${PYTHON_BIN}" -m ipykernel install --user \
    --name ceridwen \
    --display-name "Ceridwen (Vast.ai GPU)"

The same script verifies 1,988 spectra, catalogue and photometry row counts, the SSP-grid shape, and its checksum before allowing the fit.

Run the notebooks

  1. Open JupyterLab on the Vast.ai instance.
  2. Select Ceridwen (Vast.ai GPU) as the kernel.
  3. Run notebooks/ceridwen_test_spectra.ipynb for spectra only.
  4. Run notebooks/ceridwen_integrated_photometry_spectra.ipynb for the combined fit.

Local CPU and remote GPU kernels share the identifier ceridwen. Their visible names identify the active machine and backend.

The kernel forces JAX_PLATFORMS=cuda and JAX_ENABLE_X64=1 for every notebook session.

scripts/bootstrap_vast_ai.sh:95-108

kernel["env"] = {
    **kernel.get("env", {}),
    "JAX_ENABLE_X64": "1",
    "JAX_PLATFORMS": "cuda",
}

Preserve results and finish

  1. Download the executed notebooks, sampler state, and final plots.
  2. Check locally that every expected output opens correctly.
  3. Stop or destroy the paid instance after the files are safe.

Do not treat the rented machine as the permanent copy of a scientific result.
