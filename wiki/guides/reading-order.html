Reading Order

Stage 1: learn the repository

Read Project map:

  • main.py is scaffold, not a scientific entry point.
  • Project code and submodules have separate ownership.
  • The root project and Ceridwen use separate environments.

Stage 2: read small project functions

Read src/mocks.py in this order:

  1. MockSample at lines 15-23: identify stored state.
  2. true_ages at lines 26-33: follow units through Astropy.
  3. draw_redshifts at lines 36-38: identify randomness.
  4. make_mock at lines 41-108: trace z into age_obs.

Then read Project modules and Python patterns.

Stage 3: follow a data product

Read Data pipeline, then trace one Borghi object:

  1. Raw Borghi row.
  2. Matching LEGA-C rows.
  3. Joined processed row.
  4. Notebook selection.
  5. Lick-index arrays or spectrum construction.

Each step changes representation, not the underlying galaxy.

Stage 4: read notebooks as orchestration

Read Notebook map. Start with:

  1. ceridwen_test_spectra.ipynb for spectral projection.
  2. ceridwen_integrated_photometry_spectra.ipynb for composition.

Notebooks assemble; modules implement.

Stage 5: trace one Ceridwen prediction

Read these pages in order:

  1. Ceridwen architecture
  2. SSP grids to CSPs
  3. Observations and SedModel
  4. Likelihood and sampling
  5. Tests as documentation

Trace this concrete call without entering unrelated physics components:

run_sampler
  -> model.predict(theta)
  -> SedModel.apply_transforms(theta)
  -> CSPBasis_afe.predict(model_theta, observations)
  -> Photometry.predict or Spectrum.predict
  -> likelihood(data, prediction, uncertainty, mask)
