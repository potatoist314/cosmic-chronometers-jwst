Reading Order

Stage 1: Learn the repository

Read Project map. Keep these boundaries in mind:

  • main.py is a scaffold. It is not a scientific entry point.
  • The project owns its code but does not own submodule code.
  • The root project and Ceridwen use separate Python environments.

Stage 2: Read small project functions

Read src/mocks.py in this sequence:

  1. Inspect the stored state in MockSample at lines 15-23.
  2. Trace the Astropy units through true_ages at lines 26-33.
  3. Identify the random operations in draw_redshifts at lines 36-38.
  4. Trace z into age_obs in make_mock at lines 41-108.

Then read Project modules and Python patterns.

Stage 3: Trace a data product

Read Data pipeline. Then trace one Borghi object through these forms:

  1. Start with the raw Borghi row.
  2. Find the matching LEGA-C rows.
  3. Find the joined processed rows.
  4. Inspect the notebook selection.
  5. Inspect the Lick-index arrays or spectrum construction.

Each step changes the data representation. The galaxy stays the same.

Stage 4: Read notebook orchestration

Read Notebook map. Then read these notebooks:

  1. Read ceridwen_test_spectra.ipynb for spectral projection.
  2. Read ceridwen_integrated_photometry_spectra.ipynb for model composition.

Notebooks assemble the analysis. Modules implement the reusable calculations.

Stage 5: Trace one Ceridwen prediction

Read these pages in order:

  1. Ceridwen architecture
  2. SSP grids to CSPs
  3. Observations and SedModel
  4. Likelihood and sampling
  5. Tests as documentation

Trace this call path. Do not inspect unrelated physics components.

run_sampler
  -> model.predict(theta)
  -> SedModel.apply_transforms(theta)
  -> CSPBasis_afe.predict(model_theta, observations)
  -> Photometry.predict or Spectrum.predict
  -> likelihood(data, prediction, uncertainty, mask)
