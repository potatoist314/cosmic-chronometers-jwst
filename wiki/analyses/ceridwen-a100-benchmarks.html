Ceridwen GPU benchmark

Fixed short workload

The maintained Vast runner uses the joint M1_210210 likelihood. It fixes the data, grid, model, seed, sampler sizes, and timed call count. It rejects summaries with different comparison fingerprints.

scripts/benchmark_ceridwen_vast.py:23-38 · benchmark contract

WORKLOAD_ID = "m1_210210_joint_full_v1"
TARGET_ID = "M1_210210"
GRID_ID = "amist_c3k_hr_krou_afe"
GRID_SCHEMA = "2.1"
GRID_SHAPE = (5, 13, 107, 10992)
EXPECTED_PHOTOMETRY_BANDS = 11
EXPECTED_SPECTRAL_PIXELS = 3523
SEED = 20260812
NUM_LIVE = 300
NUM_INNER_STEPS = 40
NUM_DELETE = 25
REFERENCE_LOGZ_TOL = -3.0
WARMUP_STEPS = 1
TIMED_STEPS = 5
CALLS_PER_STEP = NUM_INNER_STEPS * NUM_DELETE
RESULT_SCHEMA_VERSION = 1

Documented contract: The focused test fixes 11 photometric bands, 3,523 spectral pixels, five timed steps, and 1,000 calls per step (tests/test_benchmark_ceridwen_vast.py:22-27).

Why it matters: Every GPU performs the same 5,000 post-JIT likelihood calls.

  • The first NSS step compiles the kernel and is not measured.
  • The short run measures speed and memory, not convergence.
  • It does not produce posterior parameter estimates.
  • The log Z tolerance records the reference fit configuration.
