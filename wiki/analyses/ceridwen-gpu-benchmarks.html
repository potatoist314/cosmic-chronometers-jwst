Ceridwen GPU benchmark

Each table holds every GPU type. The tables divide by measurement type.

The rows follow the architecture order: Volta, Ampere, Ada, Hopper.

H100 SXM 16,896 8,448 528, fourth generation 67 TFLOP/s 494 TFLOP/s 34 TFLOP/s 50 MB 3,350 GB/s 80 GB
  • Tensor peaks use dense operations. This page excludes sparsity peaks.
  • Each RTX card holds two FP64 units per SM. The RTX 3090 has 82 SMs. The RTX 4090 has 128 SMs.
  • Each RTX card runs FP64 at 1/64 of its FP32 rate.
  • The A100 and the H100 add an FP64 tensor path. The A100 path reaches 19.5 TFLOP/s. The H100 path reaches 67 TFLOP/s.
  • The V100 and the RTX cards have no FP64 tensor path.
  • The V100 tensor cores accept FP16 inputs. They do not accept TF32 or FP64 inputs.
  • Ceridwen uses FP32 and FP64 data. Ceridwen does not use FP16 data.
  • Core counts do not compare across tensor-core generations.
  • A hardware peak does not prove that XLA selected a tensor-core kernel.

Project synthesis: This page calculates two values. It calculates the RTX FP64 core counts from the two-per-SM rate and the SM count. It calculates the H100 dense TF32 peak as one half of the published sparsity peak.

Hardware evidence: NVIDIA Ampere GA102 white paper, Table 9 on pages 44 and 45, and the FP64 note on page 10. NVIDIA Ada white paper, Table 2 on pages 29 to 31, and the FP64 note on page 7. NVIDIA A100 architecture white paper, Table 4. NVIDIA Tesla V100 data sheet, specifications table. NVIDIA H100 architecture white paper, Table 3 on page 39, for the H100 core counts and L2 cache.

That H100 white paper marks its throughput values as preliminary. The shipping NVIDIA H100 product specifications give the H100 peaks, bandwidth, and memory size.

Speed and cost

  • The RTX 4090 was 2.33 times faster than the RTX 3090.
  • The H100 was 5.37 times faster than the RTX 3090.
  • The H100 was 2.31 times faster than the RTX 4090.
  • The A100 was 2.95 times faster than the V100.
  • The RTX 4090 offer had the lowest cost per call.
  • The cost result applies only to these three Vast offers.

Modal A100 kernel trace

The trace used the joint fit benchmark model, data, seed, and sampler settings. One warm-up step ran before the trace.

Measurement Value
Post-JIT NSS step 7.843 s for 1,000 likelihood calls
GPU stream active 94.9%
input_reduce_fusion_5 6.984 s across 564 launches, or 93.8% of GPU event time
Device-to-device copies 2.0% of GPU event time
FFT kernels 1.0% of GPU event time
GEMM and dot kernels 3.507 ms, or 0.047% of GPU event time

The GPU stayed active. One XLA reduction fusion used most of the GPU time. Host launch gaps and matrix multiplication used little GPU time.

Project synthesis: The large fused reduction limits the speed. GEMM throughput does not limit the speed. FP64 tensor cores are unlikely to explain the 2.95-fold A100 advantage over the V100.

The timeline holds no hardware instruction counters. It does not show whether a kernel issued tensor-core instructions.
